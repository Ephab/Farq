# Localization (English / Arabic, LTR / RTL)

## Architecture
- `src/lib/i18n/core.ts`: framework-free catalog lookup, `{param}` interpolation, plurals via
  `Intl.PluralRules`, formatters (`fmt.number/percent/date/time/dateTime/relative/list`), the digit
  policy (`intlLocale`: Arabic uses Western digits), and `matchesSearch` (Arabic-aware search folding).
- `src/lib/i18n/context.tsx`: `I18nProvider` + `useI18n()` → `{ t, fmt, locale, dir, setLocale }`.
  Sets `<html lang dir>`, persists to localStorage `waypoint-locale`.
- `index.html`: inline script sets `lang`/`dir` before first paint (no LTR flash).
- `src/locales/{en,ar}/<namespace>.ts`: one file per feature. `ar/<ns>.ts` is typed
  `CatalogShape<typeof en>`, so a missing Arabic key fails `tsc`. Missing keys at runtime warn in dev
  and fall back to English.

## Rules for components
- Strings: `const { t, fmt } = useI18n()`; `t("quiz.results.title")`, `t("x.count", { count })`.
  Plurals are objects: English `{ one, other }`; Arabic `{ zero, one, two, few, many, other }`.
  Never `locale === "ar" ? … : …` in components.
- Non-React modules (lib/*.ts) that produce UI text: return a key or data, translate in the component;
  or accept a `t` argument.
- Never translate IDs, API values or enums sent to the server; map enum → key for display only.
- Layout: logical Tailwind only — `ms-/me-/ps-/pe-/start-/end-/text-start/text-end/border-s/border-e/
  rounded-s/rounded-e/…`, and in CSS `margin-inline-*`, `padding-inline-*`, `inset-inline-*`,
  `border-inline-*`, `text-align: start`.
- Motion `x` values and pixel geometry are physical: multiply by `dir === "rtl" ? -1 : 1`.
- Mirror icons with `rtl:-scale-x-100` only when they mean direction (back/next, chevrons pointing
  along the reading line, "send" arrows, panel-left). Never mirror search, refresh, check, warning,
  upload/download, play, logos, charts.
- Dynamic text of unknown direction (names, titles, messages, user/AI content): `<bdi>` or `dir="auto"`.
  Machine values (emails, URLs, IDs, file names, code, keys): `dir="ltr"` or class `ltr-value`.
  Inputs for such values: `dir="ltr"` (or only when non-empty so Arabic placeholders read RTL);
  free-text inputs/textarea: `dir="auto"`.
- Dates/numbers: `fmt.*`, never `toLocaleString()` without the locale or hand concatenation.
- Search: `matchesSearch(haystack, query)`.
- Brand/product/model names stay Latin (Waypoint, Hermes, Gemini, GitHub, LinkedIn, ORCID, Outlook).
- Server/AI-generated content (roadmap curriculum, Hermes replies, email bodies) is content, not UI:
  not translated client-side; wrap in `dir="auto"`.
- Catalog gotcha: any object with an `other` key is treated as a plural. Don't name a plain sub-key
  `other` (e.g. a category label) — use `misc` and map the API value to it.
